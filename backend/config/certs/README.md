# Сертификаты для GigaChat API

Серверы GigaChat (`ngw.devices.sberbank.ru:9443` — авторизация, `api.giga.chat` — модели)
используют сертификаты Минцифры России. Их нет в стандартных хранилищах (certifi, Linux-образы
Docker), поэтому без этих файлов TLS-проверка падает с `CERTIFICATE_VERIFY_FAILED`.

Файлы подключаются **только** к HTTP-клиенту GigaChat (`app/chat/gigachat.py`) — поверх
системного хранилища и certifi. Остальные соединения бэкенда этим центрам сертификации не
доверяют. Путь задаётся `GIGACHAT_CA_BUNDLE` (файл или каталог); по умолчанию — этот каталог.

| Файл | Сертификат | Действует до | SHA-256 |
|---|---|---|---|
| `russian_trusted_root_ca.crt` | Russian Trusted Root CA | 2032-02-27 | `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31` |
| `russian_trusted_sub_ca.crt` | Russian Trusted Sub CA | 2029-07-19 | `21:55:78:50:36:C9:00:DB:B5:F1:BB:2A:15:69:C8:0C:55:59:5B:D6:BF:94:86:7A:29:BB:DD:BC:7D:88:A3:F2` |

Происхождение и проверка (10.11.2026): корневой сертификат скачан с `gu-st.ru` (Госуслуги) и
совпал с корнем, который отдаёт сам `ngw.devices.sberbank.ru`; промежуточный совпал с тем, что
отдают оба сервера GigaChat, и подписан корневым (`openssl verify`). Оба совпадают с
сертификатами, установленными в хранилище Windows.

Проверить у себя:

```bash
openssl x509 -in russian_trusted_root_ca.crt -noout -subject -enddate -fingerprint -sha256
```

Когда промежуточный сертификат обновят, достаточно заменить файл: серверы присылают его в
цепочке сами, а корневой действует до 2032 года.
